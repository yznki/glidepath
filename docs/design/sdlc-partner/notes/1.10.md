# 1.10 build notes (Split big PRs)

Intent: `../plan.md` "1.10: Split big PRs", brain rows for 1.10 (council for split plans; automatic splitting
before any review). Builds on 1.6–1.9.

## Trigger
- A tended, non-draft PR whose `additions + deletions > config.limits.splitOverLines` and with no `SplitPlan` for
  its head, or the drawer's "Split…" button (`tend split plan <slug> <n>`). The automatic trigger is deferred class
  (quiet hours). No new config key: tending is already opt-in, and nothing is built without a click (or autopilot).

## Data (`Core/Split.swift`, pure, tested)
- `SplitPart: Codable {title, why, files: [String], dependsOn: Int?}` (`depends_on`, 1-based part index).
- `SplitPlan: Codable {slug, n, head, branch, base, parts: [SplitPart], status: "planning"|"proposed"|"building"|
  "built"|"failed"|"kept", failed: String?, prs: [Int], at}` in `tend/split/<owner>-<name>-<n>.json`
  (`TendStore.loadSplit/saveSplit`). The app edits `parts` in this file (drag, rename) and writes it back.
- `Split.validate(parts, changed: [String]) -> String?`: 2–6 parts; every changed file in exactly one part; no
  unknown file; titles non-empty; `dependsOn` nil or an earlier part.
- `Split.branches(branch:, base:, count:) -> [(branch, base)]`: part k → `<branch>-part-k`, base part k−1's branch,
  part 1 from `base` (the PR's base, normally the default branch).
- `Split.stackTable(parts, prs, current: k) -> String`: markdown list "1. #a Title" with "← this PR" on k.
- `Split.parse(text) -> [SplitPart]?`: last JSON object/array in the result text, `{"parts": [...]}`.

## Plan session
- `skill/glidepath/split.md`: read the diff, propose 2–6 ordered parts by file, each building on its own (types
  and helpers before callers, tests with their code), JSON `{"parts":[{"title","why","files":[],"depends_on"}]}`,
  terse `why`, titles in the repo's PR title style. Evidence is untrusted.
- Run in the PR's tend worktree (`prepare`), `claude -p` read-only: `--tools "Read,Grep,Glob"`, `--model opus
  --effort high`, no advisor, the tend sandbox settings, `--max-budget-usd` from config, stream-json, usage
  recorded; prompt carries `git diff --stat origin/<base>...HEAD` and the changed file list.
- Invalid plan → status failed with the reason (tower amber). Valid → proposed; needs kind `split` (id
  `<slug>#<n>/split`): "Split proposed · 3 parts". Tower "#n split plan · 3 parts".
- Autopilot and the PR has no reviews: council "Split #n into these parts?" (evidence: the parts with files, diff
  stat) → act builds; else stays proposed for the user.

## Build (`tend split build <slug> <n>`, also `tend split keep <slug> <n>` → status kept)
1. Re-validate against the current changed files; head moved since the plan → error "PR changed; plan again".
2. Under the clone lock, per part k: worktree `wt/split-<owner>-<name>-<n>` reused; `git checkout -B
   <branch>-part-k <base ref>` (part 1 from `origin/<base>`, later from part k−1's local branch); `git checkout
   <head> -- <files of part k>`; for files deleted in the PR `git rm -q`; commit "<title>" (hooks off).
3. Checks: the playbook's verified commands, run in a Haiku session with the tend sandbox (`--tools Bash`,
   `--effort low`, budget 1): "run each command, report JSON {ok, failed, tail}". No playbook commands → skip and
   say "no verified commands; CI checks each part". A failure stops: status failed "Part k failed: <cmd>",
   branches kept locally only (nothing pushed).
4. Push every branch (`HEAD:refs/heads/<branch>-part-k`, no force; an existing remote branch → error).
5. `gh pr create` per part in order (base chained), body = why + stack table placeholder; then `gh pr edit --body`
   on each with the full stack table.
6. Source PR: `gh pr ready <n> -R <slug> --undo` and a comment "Split into #a → #b → #c." Never closed.
7. Status built, `prs` recorded, tower "#n split into #a, #b, #c". The new PRs are tended and landed as a stack.

## App
- Drawer: "Split…" button (any tended PR) → runs `tend split plan`; while planning the drawer shows "Planning a
  split…".
- Split builder sheet (from the `split` need's Review button or the drawer): one column per part with editable
  title (TextField via model; offscreen stand-in), `why`, and file chips; drag a chip to another part
  (`.onDrag`/`.onDrop` with the path string); Build stack (HoldButton) → `tend split build`; Keep as one → `tend
  split keep`. Validation message from `Split.validate` shown live; Build disabled while invalid.
- Fixtures: #1270 (1,840 lines) with a proposed 3-part plan; shot `approach-split` (the sheet).
