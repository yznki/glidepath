# 1.8 build notes (Merge)

Intent: `../plan.md` "1.8: Merge", brain rows for 1.8 (council for conflicts and reverts; automatic revert PRs;
autopilot merge). Builds on 1.6/1.7 (`notes/1.6.md`, `notes/1.7.md`).

## Config
- `[tend] merge = "off" | "ask" | "auto"` → `TendMerge`, parses to `off`. `ConfigEditor.setTendMerge`.
  `setTendEnabled(true)` (the Settings switch, a setup writer) also writes `merge = "ask"` when the key is absent.
- `[[repo]] merge_method = "merge" | "squash" | "rebase"` → `RepoConfig.mergeMethod`, default `merge`; unknown value
  is a config error like the other enums.
- Autopilot: `TendAction.land`, `.conflict`, `.revert`; `actor(_:autopilot:push:disagree:merge:)` gains
  `merge: TendMerge = .off`. land: autopilot or `merge == .auto` → act; `.ask` → you (callers never propose landing
  with `off`). conflict: autopilot → council, else you. revert: autopilot → council, else you.

## Core (pure, tested)
- GraphQL adds `baseRepository { defaultBranchRef { name } }` → `OpenPR.defaultBranch` (String, "" when missing).
- `Fingerprint.full` adds `base`, `mergeStateStatus`, `reviewDecision`.
- `TendDecision.decide`: also a round when `mergeStateStatus == "DIRTY"` and the PR is tendable, with a new full
  fingerprint. Urgent when approved.
- `Core/Landing.swift`:
  - `Landing.ready(pr, state) -> Bool`: `Approach.marker(pr) == 3`, tendable, no held, no stuck, no calls,
    `pr.base == pr.defaultBranch`.
  - `Landing.next(prs, states: [Int: TendPR]) -> OpenPR?`: the ready PR with the lowest number. One landing per repo
    per check: main moves, so the next one waits for a fresh read.
  - `Landing.children(of: pr, in: prs) -> [OpenPR]`: PRs whose base is `pr.branch`.
  - `Landing.detail(pr, prs) -> String`: "Ready to land · approved · 4 checks green" + " · then #a, #b" (the stack
    above it, bottom-up, via `Approach.lanes`).
  - `MainWatch.verdict(merge: [CheckState], parent: [CheckState]) -> .pending | .ok | .broke([String])`: broke when
    a check completed FAILURE/TIMED_OUT on the merge commit and the same name is SUCCESS on the parent; else pending
    while any merge check is not completed; else ok. Every check counts as required (1.6 decision).
  - `Landing.revertBody(n:, sha:, failing:) -> String`: "Reverts #n (`abc1234`). <a, b> failed on the merge commit
    and passed on the commit before it."
- `TendLanded: Codable {slug, n, title, sha, parent, at, status: "watching"|"ok"|"broke"|"reverted"|"timeout",
  failing: [String], revert: Int?}` in `tend/landed.json` via `TendStore.loadLanded()/saveLanded(_:)`; entries older
  than 7 days are dropped on save.
- `ApproachPlane.landedAt: Date?` (decodeIfPresent). Landed planes (from records < 60 min old, or still watching)
  get phase `.landed`, marker 4, label "Landed · watching main" / "Landed" / "Main broke after #n" / "Reverted in #m".
- `Approach.needs(slug, pr, state:, landable: Bool = false)` adds kind `land` (id `<slug>#<n>/land`, detail from
  `Landing.detail`) after held/stuck/calls. Revert needs come from landed records with status broke and no revert:
  kind `revert`, id `<slug>#<n>/revert`, detail "Main broke after #n · <checks>".

## CLI
- After pass two, per repo, unless `merge == .off`: skip PRs that had a round this check; `Landing.next` → actor
  `.land`: act → `land`; you → add it to `landable` (published as a `land` need).
- `land(repo, pr, prs)`:
  1. `gh pr merge <n> -R <slug> --<method> --match-head-commit <head>`. Failure → stuck "Merge failed: <stderr>".
  2. Each child: `gh pr edit <c> -R <slug> --base <default>`; tower "#c retargeted to <default>".
  3. Delete the branch: `gh api -X DELETE repos/<slug>/git/refs/heads/<branch>` (a 422 or 404 is fine: GitHub may
     have deleted it).
  4. Remove the worktree and the PR's state file (the same code `removeClosed` uses; extract `forget(repo, n)`).
  5. `sha` from `gh pr view <n> -R <slug> --json mergeCommit -q .mergeCommit.oid`, `parent` from
     `gh api repos/<slug>/commits/<sha> -q '.parents[0].sha'`; save a `TendLanded` (watching).
  6. Tower "#n landed · <sha7>"; RunState kind tend, tendAction "landed" (RunDigest title "Landed #n"), no tokens.
- `tend land <slug> <n>`: fetch open PRs, `Landing.ready` or error "not ready: <first gate that is not ok>", then
  `land`. `tend revert <slug> <n>`: open the revert PR for a landed record.
- Conflict round (`mergeStateStatus == "DIRTY"`), in `round` after `prepare`:
  - `git merge --no-edit origin/<base>` in the worktree (hooks off as every tend git call). Never rebase.
  - Clean merge: no session. Push per `actor(.pushFix(approved:))` (held when approved and ask). No PushGuard (the
    incoming code is the base branch's own). Tower "merged <base> into #n · pushed <sha7>". tendAction "merged".
  - Conflicts: `conflicts.md` (untrusted header; `git diff --name-only --diff-filter=U`; then `git diff` capped at
    300 lines) and `conflicts=<path>` in the prompt. Session resolves the markers, no commit.
    - giveup → `git merge --abort`, hard stop: stuck "Conflicts with <base> · <summary>".
    - After: `restoreGitLink`; leftover markers (`git diff --check` names "leftover conflict marker") → abort, stuck.
    - `git add -A`; PushGuard on `git diff --cached -U0 HEAD -- <conflicted files>` with no size cap, plus
      flag paths. Refusal → abort, stuck.
    - `git commit --no-edit` (git's merge message).
    - confidence low → `actor(.conflict)`: council "Push this conflict resolution?" (evidence: conflicts.md + the
      resolution diff capped 120 lines) → act pushes, else held; you → held. Otherwise `actor(.pushFix(approved:))`.
  - A conflict round handles only the conflict; CI and threads get the next round on the new head.
- Post-merge watch, after publish's inputs are built, for every watching record in a tended repo:
  - `gh api repos/<slug>/commits/<sha>/check-runs --paginate -q '.check_runs[] | [.name,.status,.conclusion] | @tsv'`
    for sha and parent (status/conclusion upper-cased into CheckState).
  - ok → status ok, tower "main green after #n". pending past 60 min → timeout. broke → status broke, failing,
    tower amber "main broke after #n · <checks>", then `actor(.revert)`: council "Open a revert PR for #n?" (evidence:
    PR title, failing checks, `git show --stat <sha>`) → act opens it; you → the revert need.
- `openRevert(record)`: under the clone lock fetch the default branch; worktree `wt/revert-<owner>-<name>-<n>`
  (`git worktree add -B revert-<n> <dir> origin/<default>`); `git revert --no-edit [-m 1] <sha>` (`-m 1` only when
  the commit has two parents); push `HEAD:refs/heads/revert-<n>`; `gh pr create -R <slug> --base <default> --head
  revert-<n> --title "Revert #n: <title>" --body <Landing.revertBody>`; record `revert` = new number, status
  reverted; remove the worktree; tower "opened revert PR #m for #n". "Main still broken after a revert" is not
  watched in 1.8.
- skill/glidepath/tend.md: a "Conflicts" section: `conflicts=` lists the files; resolve every marker keeping both
  sides' intent; if both sides changed the same logic, give up and say so; never rebase, never commit; result.json
  action `fix` (resolved) or `giveup`.
