## Self-review
- `TendPR.selfReview: SelfReview? {head, at, verdict, findings: [DraftComment], done: Bool}` and
  `TendPR.wasDraft: Bool` (last seen draft state).
- Due when `self_review` is on, the PR is tendable and not a draft, and either no `selfReview` yet or the PR went
  draft → ready since (`wasDraft` was true). Class deferred (quiet hours, per plan).
- Run: `glidepath review <slug> <n> --dry-run --again` as a child process (same binary, `InitCommand.binaryPath()`),
  parse "run <id>" from stdout, read `<scratchDir>/<id>/<owner>-<name>/<n>/final.json` (`Draft`). Record
  `selfReview`; tower "#n self-review · 2 findings" (or "· clean"). Nothing is posted (dry run).
- Findings with verdict `changes` become asks of kind `self` (id `self-<head7>-<i>`, author "self-review", path/line,
  body) in `Threads.actionable` until answered. In the round they go into threads.md like others; results:
  agree+fixed → answered, no reply; anything else → answered, tower line only. Never posted.
- Drawer/plane: taxiing or flying PRs with a self-review show "Self-review: k findings" (or "clean").

## PR description upkeep
- `Describe.block(lines: [String], checks: [String]) -> String`: `<!-- glidepath -->\n### Changes since review\n- …\n`
  + (when checks) `\n### Test plan\n- [x] \`cmd\`\n` + `<!-- /glidepath -->`.
- `Describe.rewrite(body, block) -> String`: replaces from the first `<!-- glidepath -->` to the next
  `<!-- /glidepath -->` inclusive; markers missing (or only one) → appends "\n\n" + block. Nothing else changes.
- `TendPR.changes: [String]` ("<sha7> <summary>", last 10). After a round that pushed (fixed, merged, pushed by
  `tend push`): add the line, `gh pr view <n> --json body -q .body`, rewrite, `gh pr edit <n> -R <slug> --body-file
  <tmp>` only when changed. Checks = the round's sanitized `ran`.

## Nudges
- GraphQL adds `timelineItems(itemTypes: [REVIEW_REQUESTED_EVENT], last: 20) { nodes { ... on ReviewRequestedEvent {
  createdAt requestedReviewer { ... on User { login } } } } }` → `OpenPR.requestedAt: [String: Date]` (latest per
  login, only logins still in `requested`).
- `Nudge.weekdayHours(from:to:calendar:) -> Double`: hours between, counting only Mon–Fri. Tested across a weekend.
- `Nudge.waiting(pr, now, hours) -> [(login, hours)]`: requested reviewers past `nudge_hours`.
- Needs kind `blocked` (id `<slug>#<n>/wait-<login>`): "Waiting 26 h on gadi"; Ping → `tend ping <slug> <n> <login>`:
  `gh pr comment <n> -R <slug> -b "@<login>, could you take a look when you get a chance? Thanks."`;
  `TendPR.pinged[login] = now`; at most one ping per reviewer per day (the subcommand refuses a second). Autopilot
  (`actor(.nudge)` act) pings on its own under the same limit. Tower "#n pinged <login>".

## Linear blocked comments
- `Linear.issueId(title:, branch:) -> String?`: first `[A-Z][A-Z0-9]+-\d+` in the title, else in the branch
  upper-cased (`yazan/ops-123-foo` → `OPS-123`). Tested.
- When a key is set and a PR becomes stuck, or a `blocked` wait appears: one comment per reason key
  (`stuck:<reason>` / `wait:<login>`, stored in `TendPR.linearPosted`). Body: "PR #n (<url>) is blocked: <reason>."
- Request: POST `https://api.linear.app/graphql`, header `Authorization: <key>` (personal keys have no Bearer),
  first `query { issue(id: "<ID>") { id } }`, then `mutation { commentCreate(input: {issueId: "<uuid>", body: "…"})
  { success } }`. Run with `/usr/bin/curl -sS --max-time 20 -H @<tmpfile> -H "Content-Type: application/json"
  --data-binary @<tmpfile2>`: the key goes in a 0600 temp header file, never on argv; delete after. JSON built with
  JSONSerialization. `Linear.requests(id:, body:) -> (lookup: Data, comment: (String) -> Data)` pure, tested.
- No live Linear check (only Sager's Linear exists); unit tests only.

## Daily briefing
- `Briefing {at, landed: [String], blocked: [String], did: {rounds, threads, councils, tokens}}`;
  `Briefing.compose(since:, now:, runs: [RunState], landed: [TendLanded], needs: [NeedsItem]) -> Briefing` pure.
  Landed = records since; blocked = needs (held/stuck/call/blocked) as "#n · detail"; did = tend runs since.
- The tend check writes `tend/briefing.json` once a day when now ≥ today's `briefing_time`, the last briefing is
  before it, and today is in `config.days`. Tower "Morning briefing".
- App: a briefing card at the top of Approach (Landed / Blocked / Glidepath did, Dismiss) until dismissed
  (`dismissedAt` in the file); a notification when a new one appears ("Glidepath briefing: 2 landed, 1 blocked").

## Weekly lesson consolidation
- `tend/lessons.json {lastRun}`. Once per 7 days, deferred class, per tended repo with ≥ 4 lessons:
  `Playbook.dropStale(now:, days: 60)` (lesson date older than 60 days and not re-taught), then a Haiku pass
  (`Lessons.consolidatePrompt(lines)`, same args as the lesson writer) → `Lessons.parseList(text, max:)`: lines
  ≤ 160 chars, count ≤ input; a bad answer keeps the old list. Source "consolidated", today's date.
